## 账号与本地数据隔离

网页现提供用户名注册、登录、退出，不收集邮箱；密码由 Supabase Auth 管理，本机不另存密码。用户名为 3–24 位字母、数字、下划线或连字符（支持中文字符），登录时忽略字母大小写。新账号的 SQLite、图片和临时文件按已验证的用户 ID 存在 `data/accounts/<用户ID>/`，同机切换账号不会打开另一账号的题目或文件。原有 `data/db` 与 `data/objects` 不自动归属新账号，仍作为 -3 旧数据保存。

连接登录服务时，从现有 Supabase 项目的 **Project URL** 和 **publishable key** 填入本机 `subjects-learning-3/.env` 的 `SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`；勿填写 secret/service_role key。可参考 `.env.example`。必须先应用仓库根目录的 `20261025020000_username_auth.sql` 迁移，并在 Supabase **Authentication → Providers → Email** 关闭 **Confirm email**，否则无邮箱注册会被服务端拒绝。应用使用用户名生成不可投递的内部邮箱标识供 Supabase Auth 登录，用户无须填写或看到它。由于没有真实邮箱或手机号，目前忘记密码后无法自助找回，请妥善保管密码。未配置 Supabase 时仍可使用原有本地页面，账号隔离尚未启用。

此阶段使用 Supabase Auth，仓库根目录的迁移建立用户档案与账号私有的学习目录。登录后后台尝试上报这台设备的题目、试卷、知识库、单词和文件目录；设置页可查看标题、正式题目的简短摘要、关系和校验值，并手动重试。完整题目、图片和长文仍存各设备本机，云端目录不等于内容备份；跨设备内容传输、云端备份与论坛尚未接通。当前浏览器登录会话只在本地服务进程中保存；重启服务后须重新登录。Android 客户端将在后续阶段实现。

## 2026-10-24 题库与复习系统

主导航为今日安排、题目库、知识库、英语单词和设置。拍题入口保留在今日安排与知识库，录入详情仍使用共用流程。确认后的完整架构见 [题库与复习系统架构](docs/项目资料/2026-10-24-题库与复习系统架构.md)。

- 题目库支持六科、知识库叶子题型多选、标签全部/任一、掌握状态、日期与关键词组合筛选，跨页选题保留。文字题可通过JSON预览导入；答案或叶子题型不完整者保存为草稿。
- 自由组卷进入题目库：配置顺序、分组、分值、作答空间，预览保存；历史试卷支持题目卷、答案解析卷、版本下载、复制修改和加入计划。保存时冻结题面、图片、答案与解析；编辑另存版本。
- 今日安排显示日期与星期，桌面为2×2四卡：拍照与四科录入确认、今日事项、分科待改错、今日需过关。卡片随视口调整，列表六条容量、内部滚动；窄屏改为单列。草稿、处理记录和周报告在弹层中查看。
- 错题录入仅适用于数理化生，正式入库后先进入待改错，不启动重推计时。点击“改错”确认已改错，从点击当天按当前设置计算首次重推（默认7天）；重复点击不重置日期。后续答对仍需确认过手，未过手或答错并已学习者次日目标重做。今日安排自动刷新，任务过期保留。
- 题型重推为选用功能，默认关闭。须开启总开关并选择叶子题型；关闭时未开始任务暂停并释放预算，进行中任务允许完成，暂停分卷不会被误算为整轮完成。
- 英语单词独立管理：手动/查词选择收录、拍照提词、TXT/Markdown/CSV/JSON词表预览导入，来源与义项合并，标准释义和个人认可答案分别保存。两种过关模式、同词性无序匹配、人工裁决、错词重练、自动保存与续做均落库。
- 单词默认新词和复习合计20词/日，按1、3、7、15、30天逐阶段复习；每日额度、时刻、模式、范围、顺序和间隔可设置，设置不覆盖已生成任务。单词不占四科75分钟预算。
- 本地服务每分钟检查排期和提醒；通知使用 Windows 原生 Toast，自动注册本应用通知身份并修复开始菜单快捷方式，点击打开本地任务。取得 Windows 通知中心回执后才记录成功；自动提醒与手动测试都保留投递结果和失败原因。应用未运行时，下次启动补办；同日同类提醒持久化去重，失败最多尝试3次。设置中可发送测试通知。勿扰、专注或全屏状态可能只收入通知中心。实现依据：[Microsoft桌面通知说明](https://learn.microsoft.com/en-us/windows/win32/shell/enable-desktop-toast-with-appusermodelid)。

## 目录与实现链路

```text
backend/app/       FastAPI 接口、业务规则、SQLite 模型及本地识别
backend/tests/     当前接口、数据保护、识别及学习流程回归测试
frontend/src/     React 正式页面与交互回归测试
frontend/dist/    正式网页构建，启动服务必需
scripts/          启停、开发构建、模型准备、公式工作进程与打包
data/            正式数据库、原图、题目版本、模型清单及备份
docs/项目资料/   当前业务规则与待展开的功能范围
version.json      版本、识别方式与端口配置
```

前端入口为 `frontend/src/main.tsx` → `app/App.tsx`。当前正式学习页面、题目库、自由组卷和单词系统集中在 `features/learning`。旧的并行页面实现已移除。

请求通过 `frontend/src/api/client.ts` 的同源 `/api/v1` 进入 `backend/app/api/v1/router.py`，由 `modules/learning`、`questions`、`papers` 等业务模块处理。正式环境由 `backend/app/main.py` 提供网页、静态资源、媒体和深层链接回退；未知 API 保持 404。

`core/config.py` 将默认及相对数据目录固定到本项目，避免从其他目录启动时误建数据库。`db/session.py` 启用 SQLite 外键、WAL 和写入等待；原件与内容版本通过 `storage/local_store.py` 按内容哈希保存。正式数据位于 `data/db` 与 `data/objects`，不能按缓存清理。OCR 使用项目数据目录内的模型配置，缺省读取仓库 `runtimes/models/local-ocr/manifest.json`；`data/backups` 保留迁移前备份。

知识库使用 `api/v1/knowledge_contents.py` 与 `modules/learning/knowledge.py`；节点、条目、标签和原图均落库，编辑有修订校验。知识库导出包含原图；导入合并知识库内容，不替换题库、做题历史和排期。完整业务规则见 [功能逻辑与用户使用链路](docs/项目资料/项目功能逻辑与用户使用链路.md)，其中待展开和远期功能不代表均已实现。

## 开发与维护

在本目录运行 PowerShell：

```powershell
# 开发网页：按 version.json 启动后端，再启动 5173
./scripts/dev.ps1

# 构建正式网页
./scripts/build.ps1

# 后端回归：测试库独立于正式数据
. ../scripts/runtime.ps1
& $python -m pytest -q -p no:cacheprovider --basetemp=data/tmp/pytest-check

# 前端回归
Push-Location frontend
npm test -- --run
Pop-Location
```

开发服务通过 Vite 代理 `/api` 和 `/media`；`dev.ps1` 从 `version.json` 读取后端端口。正式构建固定使用同源 API。公式渲染超时或运行程序缺失时，PDF 保留公式原文，避免整张导出失败。修改后端代码后，停止并重新启动服务；启动脚本会校验版本及实际数据目录，不复用另一项目的服务。改动前端代码后须重新构建。

保留的模型准备工具：

| 功能 | 脚本 |
| --- | --- |
| OCR、布局与基础公式 | `setup-local-ocr.ps1`（公式加 `-Formula`），调用 `prepare-local-ocr.py`、`prepare-local-formula.py` |
| 基础公式运行工作进程 | `local-formula-worker.py`，由后端调用 |
| GLM-OCR | `setup-document-ocr.py` |
| UVDoc | `setup-document-rectification.py`，调用 `export-uvdoc-grid.py`；转换依赖通过仓库 `scripts/setup.ps1 -InkTools` 安装 |
| LaMa 局部修复 | `setup-diagram-repair.py` |
| 笔迹分割 | `setup-ink-erase.py --model segment`，再用 `runtimes/ink-erase/Scripts/python.exe` 执行 `export-exam-ink-onnx.py` |
| 公式打印 | `setup-document-renderer.ps1`；正式运行调用 `render-intake-formula.cjs` |

准备脚本会下载或转换模型，正常启动不必重复运行。全新恢复统一使用上一级 `scripts/setup.ps1`，它根据已锁定的主环境依赖安装。

完整备份前先停止服务，再通过共享运行配置取得 `$python` 后运行 `& $python scripts/package-project.py`。脚本使用 SQLite 备份接口，校验数据库及登记文件是否入包，生成带时间戳的 ZIP 和校验 JSON 到上一级 `归档/版本包`，不会覆盖旧包。旧版本 ZIP 只是历史快照，不等于当前源码。恢复到新目录后，按仓库安装说明恢复运行库和模型，再启动。
