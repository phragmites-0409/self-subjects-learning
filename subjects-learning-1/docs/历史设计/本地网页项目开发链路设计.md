# 1. 范围与术语

## 1.1 本轮范围裁定

| 项目      | 裁定                                                                                    |
| ------- | ------------------------------------------------------------------------------------- |
| 顶层板块    | **5 个**：主页 / 拍题与对话 / 知识库 / 学习计划 / 设置（详见 §4）                                           |
| 知识库     | **两套并列逻辑**：数理化生**以题型为核心推进**；语文英语**以记录记背为核心**（详见 L2）                                   |
| 过手      | **知识点记背过手（仅数理化生）+ 题型过手（仅数理化生）+ 英语单词过手**；语文文言及古诗的专门过手机制**【暂缓】**；**语文英语知识库不参与过手、不产生推送** |
| 英语      | 知识库只收**作文素材**；单词走**独立词库**；语法/阅读答题方法不进知识库                                              |
| 错题      | **取消错题本体系**：错题是题目上的一个**状态标记**，找错题靠按标记筛选（详见 L3）                                        |
| 答案      | **主路径是我自己拍照上传或输入**；AI 演算补答案仅作兜底（详见 L1）                                                |
| 批改      | **AI 判对错**（客观题优先规则判定）；**不自动改题目标记**，"标为错题"由我点击                                         |
| AI 写入   | **AI 的任何产出都只是提案**：题目、知识点、题型、解题方法、记录条目、作文素材、单词的落库**全部由我手动操作**（硬约束，详见 L2 与 §7）          |
| 批改 / 推送 | 推送是"组卷 + 每日错题 + 批改待办 + 过手复习"的**任务编排器 + 提醒**，不是消息系统；时间与周期可设置                           |
| 事项与日清周清 | **本轮做**；**不做**与外部日程应用联动                                                               |
| 账号      | **本轮做**：默认账号自动登录 + 可设密码/切换/新建；全表 `owner_id` 落到查询过滤（详见 L10）                            |
| 迁移      | **引入 Alembic**，替换 `models.py` 的手写 SQLite 迁移                                           |
| 明确不做    | 设备端 API、Git 版本控制、考情统计（远期）、课外内容（删除）                                                    |

> **与旧版（`项目规划.txt` 的 9 板块）对照**：主页 / 拍题 / 知识库 / 设置 **保留**；**错题本取消**（改为题目标记）；**组卷库并入知识库**（组卷页签）；**每日错题并入学习计划**的每日任务；考情统计转远期；课外内容删除。

## 1.2 术语

| 术语           | 含义                                                                        |
| ------------ | ------------------------------------------------------------------------- |
| 题目 / 题目版本    | 唯一的可复用内容源；每次解析或修订产生**不可变版本**                                              |
| 两棵树          | **知识点树**（考什么，按章节）与**题型树**（怎么解，按模块/模型）是两棵独立的树，不共用层级                        |
| 主题型          | 每道题**唯一**的题型归属（`questions.type_node_id`），决定它落在哪个题型的题目池里；可为空（语文英语题目）       |
| 题目池          | 某个主题型下的**全部**题目；**自由组卷的候选来源**                                             |
| 题目标记         | **状态轴**（非错题 / 错题 / 已过手）+ **类别轴**（重点题 / 模板题 / 难题，空 = 普通题）；另有 AI 给的**用时档位** |
| 用时档位         | AI 给出的"短 / 中 / 长"用时预估档位，用于时间预算装题与筛选；**不是难度**                              |
| 解题方法         | 挂在**题型节点**下的一般化陈述（核心模型、公式、常规步骤、思路、方法），来源三种                                |
| 记录库（语文英语）    | 语文英语的知识库：分类树 + 条目（诗词、文言、阅读套路、成语、作文素材、语用）。**纯记录与查阅——不标记、不推送、不过关**          |
| 过手           | 从"不会"到"确认掌握"：知识点靠定期记背 + 过关；题型靠"已过手错题占比达阈值后进入定期推送"；单词靠规则匹配 + 人工裁决          |
| 归档入库         | 把一段对话或外部聊天记录整理为**一条条目**（知识点内容 + 解题方法 + 例题演示），确认后**挂到指定题型的"解题方法"下**        |
| 例题演示         | 归档条目里附带的示范题片段，**属于条目内容**，不是题库题目；要成为题目须另行确认                                |
| 提案（Proposal） | AI 的整理结果或建议，**只是待确认草稿**；我手动 apply 才落库                                     |
| 补答案          | **兜底**：仅当没有答案可上传时，AI 演算给出答案与步骤，我确认后写入新版本                                  |
| 每日任务         | 某一天固定的待办集合，由调度器生成，刷新不变                                                    |

# 2. 设计原则

**继承（批次 1 spec，继续有效）**

1. 本地单体应用：FastAPI + SQLite + 本地对象目录；不引入 Supabase/MySQL/Redis/Celery。
2. **代码与数据分离**：`data/` 存数据库、对象、临时、日志、备份。
3. SQLite 只存**轻量元数据与关系**；解析、对话、导入内容 gzip 压缩后存对象目录；**图片与 PDF 不入库**。
4. AI 只由后端调用，**API Key 永不返回浏览器**；用户文本与图片是**不可信数据**，不能覆盖系统提示词。
5. 长任务与 AI 网络调用**不放在数据库事务内**；默认只监听 `127.0.0.1`。

**本版新增**

6. **先判定、后解析**：信息不完整或超出高中范围时不得进入正式归档。
7. **AI 永不自动写入知识库与题库（硬约束）**：AI 只能产出**提案**，题目、知识点、题型、解题方法、记录条目、作文素材、单词的落库**一律由我手动执行**。目的是**防止污染知识库**——库里每一个字节都是我亲手放进去的。
8. **过手靠证据**：知识点靠"过关动作"、题型靠"题目池里错题的状态"、单词靠"规则匹配 + 人工裁决"；不用 AI 打分代替判定。
9. **原件优先**：手写、答案、作答等原始材料**永久保留可回看**，可压缩但不可丢弃。
10. **推送即任务编排**：推送的产物是"当天要做的事"，不是消息流。
11. **可追溯**：每次 AI 调用落地审计记录（模型、策略版本、输入哈希、用量、延迟）。

**非目标**：多用户注册 / 组织权限 / RLS / 云端同步 / 移动端 / 消息推送 / 设备端 / Git / 考情统计 / 课外内容（云端相关一律见配套文档）。

```
┌───────────────▼──────────────────────────────────────────────┐
│ FastAPI（backend/app）                                        │
│  api/v1/*    路由层：参数校验、DTO、错误码                       │
│  modules/*   领域服务：accounts / questions / conversations /   │
│              knowledge / papers / grading / vocabulary /       │
│              composition / study / jobs                       │
│  ai/*        AI Gateway：提示词注册表 → provider → 校验 → 审计   │
│  storage/*   对象存储（哈希寻址、原子写、路径防护）               │
│  documents/* 图片管线、压缩 JSON、PDF 生成                       │
│  core/*      配置、错误、安全                                   │
└───────────────┬──────────────────────────────────────────────┘
   ┌────────────▼─────────────┐   ┌────────────────────────────┐
   │ SQLite（data/db）         │   │ 本地对象目录（data/objects） │
   │ 元数据/关系/状态/索引      │   │ 原图/缩略图/压缩内容/PDF/    │
   │ WAL + 外键 + busy_timeout │   │ 手写原件/答案原件/作答/导入   │
   └──────────────────────────┘   └────────────────────────────┘
```

## 3.2 运行时与硬约束

- 后端 `uvicorn`（`127.0.0.1:8000`，由 `scripts/dev.ps1` 启动）；前端 Vite `:5173`，生产构建由后端 SPA fallback 托管。
- **必须单进程**：uvicorn 单 worker + 进程内调度器与 Job worker；禁止多进程写库。
- 调度器为**进程内 asyncio 循环**（L7），不引入外部定时服务。
- 长任务走进程内后台队列 + `jobs` 表状态机（§11.3）。

# 5. 端到端链路

## L0 录入与资产链

**入口**：拍题解析页、批改页、答案上传、知识库导入页。

1. `POST /assets` → MIME 白名单（jpg/png/webp，≤10 MB）。
2. `normalize_image`：EXIF 转正、最长边 2400、转 WebP、生成 640 缩略图。
3. 对象存储按 sha256 前两位分目录；写文件走临时文件 + `fsync` + `os.replace`。
4. `Asset` 按 sha256 去重（同哈希复用）。
5. **改造点**：当前上传即建题；改为按 `purpose` 分流（`question` / `answer` / `submission` / `handwriting` / `import`），**只有拍题用途才创建 Question**。

**边界**：非法 MIME 415；超限 413；图片不可解码 422；路径穿越由 `path_for` 拒绝。

## L1 拍题解析链

1. `POST /questions/{id}/parse` → 创建 Job 进后台队列（**改造**：现为同步执行）。

2. **前置判定**（`preflight`）：是否高中题、题干/图形/公式是否完整、是否属于六科。
   
   - `needs_more_info` → 停在待补拍，返回需补充的具体项；`not_supported` → 明确拒绝；`uncertain` → 允许继续但全程标记。

3. **结构化解析**（`solve`）→ `QuestionContentV1`（题干、选项、学科/年级、题型、知识点、方法、条件、目标、步骤、答案、**用时档位（短/中/长）**、易错点、不确定项）。

4. **AI 复核**（`review`）→ `ReviewResult`。

5. **暂存解析结果（≠归档）**：写一条 `QuestionVersion`（压缩内容 + sha256）并把 `current_version_id` 指向它，题目 `status='parsed'`（**待确认**）；同时写 `AIRun` 审计。**先暂存是必需的**：前端要能展示结果供我确认、AI 原始输出要不可变保留以备审计、我可能不确认就离开。

6. **用户确认（改造重点）**：解析完成 ≠ 归档。展示结果与不确定项，我确认分类（学科/题型/知识点/标签，可改 AI 建议）后 `POST /questions/{id}/confirm` 才把 `status` 置 `approved`，并给该版本打上 `review_status='user_approved'`。**题型与知识点的输入框下方必须给出知识树匹配提示，可一键采纳规范节点名**（见 L2）。
   
   > **第 5 步与第 6 步不冲突**：第 5 步写的是**内容**（一个不可变版本），第 6 步改的是**状态**（approved）。**只有 `approved` 的题目才能进入组卷候选**，`parsed` 草稿题不入卷。

7. 归档后可选：改标记（L3）、归档入库（L2）、加入组卷候选（L6）。

8. **答案的两条路径**：
   
   | 优先级     | 路径       | 流程                                                                                             |
   | ------- | -------- | ---------------------------------------------------------------------------------------------- |
   | **主路径** | 我自己上传答案  | 拍答案照片（教辅/答案册/我自己写的）或输入文字 → AI 只做**识别与结构化** → 我**校对确认** → 写入**新版本**（答案图存 `answer-images`，可回看原图） |
   | **兜底**  | AI 演算补答案 | 仅当题目本身没答案、我也没答案可上传时（`answer_draft`）→ AI 给出演算 + 答案 + 不确定项 → **我确认后写入新版本**                       |
   
   两条路径都**不覆盖历史版本**（旧试卷引用的版本不受影响）；**没我确认就不入库**。

> **关键约束**：`approved` 只能由我的确认动作产生；AI 复核通过只是"建议归档"。
> **题内追问**：绑定题目，取当前版本内容 + 最近 8 条消息 + 有界摘要；`client_request_id` 幂等（已实现，保留）。

## L2 知识沉淀链

### L2.1 知识库的结构（本设计的核心约定）

**数理化生与语文英语都有知识库，但是两套不同的逻辑，并列而非包含。**

| 对比项  | 数理化生（四科）                  | 语文英语（两科）                              |
| ---- | ------------------------- | ------------------------------------- |
| 核心   | **以题型为核心推进**              | **以记录记背为核心**                          |
| 主轴   | 题型树（怎么解）                  | 记录分类树（记什么）                            |
| 内容形态 | 解题方法 + 题目池                | 条目（文本 / 拍照原件 / 导入 / 对话整理）             |
| 推进方式 | 题目池里的错题 → 过手 → 重推（见 L4.2） | **无推送**：纯记录与查阅，我需要时主动去查               |
| 与题目  | 题目挂在题型下，是核心资产             | 不挂题目；题目仍可解析/追问/打标记/组卷，但不进题型体系         |
| 内容分类 | —                         | 照旧：语文（诗词/文言/阅读套路/成语/作文/语用）、英语（作文素材子类） |

```
数理化生（以题型为核心推进）——树的层级自由编辑：根=科目，其余全是节点，挂到哪个父节点由我决定，层数不限
│
├── 主轴：题型树（怎么解）
│     科目（根）
│       └── … 任意层级的**分类节点**：只用于组织，不挂题目、不过手、不推送 …
│             └── **叶子题型**（挂具体题目）← **只有它是可推送的题型**，父节点涵盖范围太大，不能独立推送
│                  ·【解题方法】核心模型 / 公式 / 常规 / 常见思路 / 常用方法
│                        来源：①我写的 ②拍照上传 ③与 AI 对话整理
│                  ·【题目池】属于该题型的全部题目（每道题自带解析与答案）
│                        两个标记轴：状态轴（非错题→错题→已过手）
│                                    类别轴（重点 / 模板 / 难题；空 = 普通题）
│                        另有 AI 给的用时档位（短/中/长）用于估时
│                    ── 题目池中全部题目都在自由组卷范围内
│                    ── 找错题 = 按标记筛选（无"错题本"体系）
│                  · 过手：**已过手错题占比 > 阈值（默认 80%）后进入定期推送**；推送中又出错 → "可能有问题"（详见 L4.2）
│
└── 辅助：知识点树（考什么，供查阅与记背）——同样层级自由
      科目（根）→ … 分类节点 …
        └── **叶子知识点** ← 挂内容、参与记背过关
          ·【内容】课本原文 / 概念 / 公式
          ·【关联题目】题目 ══ 多对多 ══ 知识点
          · 过手：标记"不会" → 定期记背（默认 2 天）→ 过关 → 已过手

语文英语（以记录记背为核心）
└── 记录分类树 → 条目（层级自由；纯组织用途，不推送）
     · 内容：文本 / 拍照原件 / 外部导入 / 对话整理
     · **主动查阅：不标记、不推送、不过关**
     · 英语单词不在此建节点，走独立词库（L4.3）
```

**树的两条结构规则**

| # | 规则 | 说明 |
|---|---|---|
| **A** | **层级自由、层数不限** | 根是科目，其余都是普通节点；**挂到哪个父节点由我决定**，不要求"章/节/模块"齐全，也不自动补空节点 |
| **B** | **只有叶子节点是"题型"** | 题型 = **挂了题目的叶子节点**；**父节点只是分类**——不挂题目、不参与过手、**不作为可推送题型**（涵盖范围太大）。知识点树同理：**记背过手只挂在叶子知识点上** |

**由此产生的两条一致性约束**（系统强制，避免出现"半题型"）：

1. **挂题目时**：目标节点必须没有子节点（是叶子）；若是分类节点 → 拒绝并提示"请挂到其下的题型节点"。
2. **加子节点时**：若该节点已挂题目 → 先提示迁移（提供**一键把题目迁到指定子节点**），迁移完成后它才成为分类节点。

不变式因此始终成立：**题目只挂在叶子上，叶子就是可推送的题型。**

**数理化生的四条硬约定**

| #   | 约定                                             | 理由                                          |
| --- | ---------------------------------------------- | ------------------------------------------- |
| 1   | **知识点树与题型树是两棵独立的树**                            | 知识点按章节、题型按模块与模型；塞进同一棵树会让"章"节点既要挂知识点又要挂题型    |
| 2   | **每道题有且只有一个主题型**（`type_node_id`，**且必须挂在叶子题型上**），另有可选的**变式关系** | 对应项目规划"标明属于哪个题型或是哪个模型的变形"；题型过手与题目池因此有确定依据   |
| 3   | **模板题与难题都是题目**（有题干与解析、可组卷）                     | 若只是文本，就进不了题目池与组卷                            |
| 4   | **"错题"只是题目上的状态标记，不是一个体系**                      | 题目只存在于题目池一处，找错题靠筛选——这样就不会出现"同一道题在两处存在"的复用关系 |

**层级不强制**：`科目 → 章 → 节 → 知识点` 中的"节"是可选的，知识点可**直接挂在"章"下**（题型树的"模块"同理）。因此：`parent_id` 允许任意父子关系、不缺中间层也不自动补空节点；层级名称只是**标签**不是约束；导航支持**直达任意深度**（目录、可点击面包屑、搜索）；面包屑显示**真实路径**，不伪造中间层。

### L2.2 题型节点内部：解题方法与题目池的关系

题型 = 一个**解法模型**，由两种材料构成，二者是**"一般"与"特殊"**的关系，**不是并列的两份资料**：

| 材料       | 是什么                                     | 与对方的关系                                        |
| -------- | --------------------------------------- | --------------------------------------------- |
| **解题方法** | 该题型的一般化陈述（核心模型、公式、常规步骤、思路、方法），脱离具体数字也成立 | 是题目池的**抽象与提炼**；模板题是它的示范，我写的/拍照的/对话整理的只是它的不同载体 |
| **题目池**  | 该题型的**具体实例**                            | 是方法论的**载体与检验**                                |

三种题目在这个关系里的角色：**模板题**＝方法的示范；**错题**＝方法未被掌握的证据；**难题**＝方法的边界；**普通题**＝练习。

由此产生三个功能方向：**归纳**（题目 → 方法：`type_summary` 出草稿，我确认后写成方法条目）、**演绎**（方法 → 题目：组卷）、**检验**（方法 ← 题目：题型过手）。

> **不做"题目 ↔ 具体方法条目"的关联**：每道题自带解析与答案（自足单元），而解题方法是**题型级的整体**。所以每个题型下只需呈现两样：**该题型的解题方法 + 属于该题型的题目**。

**关系一览**

| 关系        | 类型              | 说明                       |
| --------- | --------------- | ------------------------ |
| 题目 → 题型   | 多对一（主题型）+ 变式关系边 | 一题一个主题型；"某题型的变式"用关系边表达   |
| 题目 ↔ 知识点  | 多对多             | 一题考多个知识点；一个知识点被多题考       |
| 题目 → 标记   | 题目自带的两个标记轴      | 状态轴 + 类别轴；状态变更保留**极简日期** |
| 题型 → 解题方法 | 一对多             | 内容条目，三种来源                |
| 知识点 → 内容  | 一对多             | 内容条目（含课本原文）              |
| 题目 ↔ 试卷   | 多对多             | 组卷，固定题目版本快照              |

### L2.3 知识树是展示册 + 归类归位

**定位**：三棵树都是**展示册**——穷举各自的节点，展示**分支链条**与**从属关系**。`KnowledgeNode.tree ∈ {knowledge_point, question_type, record}`；`parent_id` 表达从属，`path` 承载分支链条；`KnowledgeEdge` 表达横向关系（变形/前置/对比）；节点带 `scope_json`（校内/校外/重点，**校外节点不进入过手推送**）。

**题型与知识点走同一套归位流程**：

1. **AI 产出建议**（解析时给出题型与知识点建议值，AI 只建议、不决定归类）；
2. **我在输入框确认或编辑**；
3. **输入框下方的匹配提示（关键）**：实时按相似度列出候选节点，**点击即采纳规范名**，一次点击完成归位。**候选只列叶子题型**——父节点是分类，不能作为归类目标；若 AI 的建议命中的是分类节点，提示"这是分类，请选其下的题型或新建"；
4. 没有合适的 → 新建叶子题型，或暂时留为未归位。

> **为什么必须有匹配提示**：题型最大的风险不是"匹配错"，而是**同一类题型被笔误拆成多个写法**（"单调性"/"函数单调性"/"单调性的判断"），一旦拆开，过手统计与题型重推就被切碎。在输入那一刻给候选，等于从源头收敛。

**树侧的认领写法（事后兜底与别名）**：**只对叶子题型有意义**。节点保留 `match_patterns_json`（如 `["单调性","函数单调性","单调性的判断"]`），做**包含匹配**，作用是"为 AI 建议提供候选 + 兜底历史自由文本"。配套：

| 机制                       | 说明                                             |
| ------------------------ | ---------------------------------------------- |
| 从属继承                     | 归位到叶子后同时属于其全部祖先节点（靠 `path` 前缀一次查出子树）           |
| 未归位清单                    | 没有任何节点认领的写法进清单（派生查询），树页醒目展示，**一键挂载**           |
| 人工覆盖 `knowledge_matches` | `pin` 强制挂载 / `exclude` 剔除误匹配，优先级高于自动匹配         |
| 多命中                      | 命中多个**题型**节点 → 提示我择优确定唯一主题型；命中多个**知识点** → 全部保留 |
| 疑似重复检测                   | 名称或认领写法高度重叠的节点，提示"疑似同一题型"并建议合并                 |

> **注意**：题型归属是**存储的确定关联**（`type_node_id`），认领写法**不再是归属依据**——它只负责给建议、兜底旧数据、维护别名。改认领写法不修改已确认的归属。

### L2.4 三种内容来源（AI 只整理，写入由我执行）

1. **题目导入**：归档时题型与知识点按 L2.3 的归位流程确认；知识点与变式关系写 `QuestionKnowledge`。

2. **外部导入**：粘贴文本或上传 TXT/MD/JSON → 原件存对象目录 → AI 整理为候选节点（含归属哪棵树、哪个节点的建议）→ 预览 → 我逐条决策（`merge`/`create`/`tag_only`/`ignore`）→ **我点"应用"才落库**；原件保留可回看。

3. **对话 / 外部聊天记录归档入库**（统一管线，两个输入源：本应用对话 L9、外部聊天记录）：
   
   - **落点**：**统一挂到"该题型的解题方法"下**——我指定一个主题型，条目就挂在该题型的解题方法集合里，便于之后按题型查找与再次阅览。
   - **条目内容**：`知识点具体内容`（概念、公式、要点）+ `解题方法 / 步骤` + `例题演示`（可选，示范题片段，**属于条目内容**）。
   - **流程**：AI 整理成草稿 → 预览可编辑 → 我在**带匹配提示的输入框**里选定主题型 → **我点"应用"才落库** → 原始记录与提案存对象目录，可追溯。
   - 若草稿里含完整题目：AI 只能**额外给出"创建为模板题"的提案**，由我确认后才写入题库。

**手写入库**：拍照 → 原图存 `handwriting-original`（不删除、不压缩）→ AI 识别文字与结构 → **我逐条校对确认后才落库**为知识点 / 题型解题方法 / 记录条目。`KnowledgeContent.source='handwriting'` + `source_asset_id` 关联原件。

## L3 题目标记与筛选链

题目只有一处归属——**题型的题目池**。"错题"是题目上的**状态标记**，不是独立体系；**没有错题本、没有"题目↔错题本"关联表**。

| 轴                        | 取值                                         | 默认          | 说明                                         |
| ------------------------ | ------------------------------------------ | ----------- | ------------------------------------------ |
| **状态轴** `state`（单选）      | `normal` 非错题 → `error` 错题 → `mastered` 已过手 | `normal`    | **保留"本身不是错题"的默认态**；可回退（已过手又错 → 回到 `error`） |
| **类别轴** `roles_json`（多选） | `key` 重点 / `template` 模板 / `hard` **难题**   | **空 = 普通题** | 普通题不存冗余标记                                  |

> **没有"难度"这个维度**：AI 不评难度，难度也就没有数据来源与独立用途；**"难题"只是类别轴上的一个手选标签**，不单独设字段。

**极简时间**：标为错题的日期 `error_marked_date`、过手日期 `mastered_date`（**只记日期**）。用途仅两个：①每日错题推送筛"前一天标为错题且未过手"的题；②自动组卷的"掌握最慢"维度（`mastered_date − error_marked_date`）。

**不保留**：复盘轮次、错因分类、独立的错题筛选维度。

**改标记的入口**：拍题解析归档后（题目详情/题目视图）、批改结果页（**我主动点击**）、题型题目池里直接改。

**按标记查找**：知识库·知识树的**题目视图**，按 学科 / 题型 / 知识点 / 状态标记 / 类别标记 / 日期区间 / 关键词 筛选；组卷候选复用同一套筛选器。

> 所有"易错点/薄弱点"一律由**知识点与题型维度上的错题数量**推导，不依赖错因标签。

## L4 过手闭环（三类）

### L4.1 知识点记背过手

**适用范围**：知识点树上的**叶子知识点**（分类节点不参与记背过手）——做题或查阅时标记"不会"，进入"待记背"，按周期推送记背，过关后转"已过手"。

```
未学习 ──(标记"不会")──▶ 待记背 ──(定期记背推送)──▶ 过关检测 ──通过──▶ 已过手
   ▲                                                     │
   └───────────────(过关失败，回到待记背)─────────────────┘
```

- `KnowledgeNode.mastery_status ∈ {not_learned, marked, passed}`（知识点树与题型树共用）。

- **知识点记背推送（两个用户可设项 + 顺延机制）**：
  
  | 设置项         | 说明                       |
  | ----------- | ------------------------ |
  | 正常推送时间      | 周期（默认 **2 天一次**）+ 当日推送时刻 |
  | **最高单日推送量** | 单日最多推多少条                 |
  
  **生成规则**：到推送日按队列顺序取出 `min(待记背数量, 最高单日推送量)` 条；**超出的一律顺延到下一个推送日**——**积压绝不突破每日上限**。这就是"按积压量动态调整"的实现方式：**不是改周期、也不是加量，而是顺延**。
  **是否到推送日**：记 `last_pushed_date`，当 `今天 − last_pushed_date ≥ 周期` 才生成任务（对服务重启与中途改周期都稳健）。
  **队列顺序**：默认按"标记为不会的日期"升序（先标记先推），同日的按节点 `sort_order`；过关的移出队列，不过关的回到"待记背"并重新排队——因此不会有内容被无限期饿死。
  **积压可见**：学习计划页显示"待记背 N 条 / 今日已推 M 条 / 按当前上限约需 X 天清空"，让顺延是可见的而不是静默的。

- 过关判定方式**待确认**（自评 / AI 出题 / 可切换，本设计按**可切换、默认自评**）；字段 `mastery_mode`。

- 事件留痕 `mastery_events`、过关记录 `mastery_attempts`。

### L4.2 题型过手

**推送单位 = 叶子题型**：只有**挂了题目的叶子节点**进入推送队列；父节点是分类，涵盖范围太大，**不作为可推送题型**。

```
building ──(出现错题)──▶ checking ──(已过手错题 ÷ 总错题 > 阈值[默认 80%])──▶ solved(high)
                                                                                  │
                                              (连续 2 轮全对) ────────────────────▶ solved(low)
                                                                                  │
                                              (连续 3 轮全对) ─▶ 提醒"可永久停推" ─(我确认)─▶ retired

solved(任一频率) ──(该轮出现错误)──▶ suspect ──(该轮错题再次全部过手)──▶ solved(high)，连对计数清零
```

- `mastery_status ∈ {building, checking, solved, suspect, retired}`；另有 **`push_frequency ∈ {high, low}`**（仅在 `solved` 下有效）。
- **进入推送的门槛**：**已过手错题 ÷ 总错题 > 阈值**（默认 **80%**，用户可改）→ `checking` 转 `solved`，**默认先高频**。**总错题为 0 时不进入推送**（节点页提示"先练题"）。节点页须显示"已过手错题占比 X% / 错题 M 题 / 已过手 K 题 / 题目池 N 题"。
- **"可能有问题"（`suspect`）**：这一题型**曾经已过手（`solved`）**，但在**新一轮的定期推送中又重新出现了错误**。它与 `checking` 的区别在**历史**：`checking` = 从未解决过；`suspect` = **我自以为掌握了、实际还没掌握**——这是最有价值的一条信息。
- **回到 `solved`**：该轮出现的错题**再次全部过手**后回到 `solved`，且**频率重置为 `high`、连对计数清零**（出了错就要重新验证）。
- **降频与停推**：`solved(high)` **连续 2 轮全对** → 转 `low`；`solved(low)` **连续 3 轮全对** → **系统只提醒**"该题型可以永久不再推送"，**是否停推必须由我确认**（确认后 `retired`，我也可以选择继续推）。低频间隔**随连续全对次数动态拉长**（15 → 20 → 30 天）。

**重推的排期与抽题（完整逻辑）**

- **频率**：高频 **7 天一次**；低频 **15 天起、随连续全对动态拉长到 30 天**。**进入推送后，是否到推送日只看周期**（不由状态变化触发）；状态只被推送**结果**改变。

- **抽题范围**：该题型题目池中**除"未过手错题"以外的全部题目**——未过手错题还在过手流程里消化，**不参与重推随机**。

- **硬性去重**：**上一轮推送过的题目，本轮一律不再抽中**（是排除，不是降权）。若排除后可用题目不足单次题量 → 取实到数量；若可用为 0（题目池太小）→ **跳过本轮并提示"该题型题目太少（N 道），无法满足不与上一轮重复"**，不生成空卷。因此单次题量隐含约束 `题目池 ÷ 2`。

- **加权随机**（多因素相乘后归一化、无放回抽样）：
  
  | 因素             | 权重倍数（默认，可调） |
  | -------------- | ----------- |
  | 基线（非错题、从未推送过）  | ×1.0        |
  | 类别 = 重点题 / 难题  | ×2.0 / ×1.8 |
  | 状态 = 已过手（曾为错题） | ×2.0        |
  | 曾推送过且做对        | ×0.4（降低重复率） |
  | 曾推送过但做错        | ×1.5        |

- **确定性**：`seed = hash(node_id + 推送日期)` → **当天抽出的题固定**，刷新不重抽、可审计（与"当天任务固定"一致）。

- **轮次记录**：新增 `type_push_rounds`（`node_id, round_no, pushed_date, question_ids_json, size, frequency, correct_count, wrong_count, result(all_correct/partial/wrong), completed_at`）。连对计数与停推提醒**由它派生，不另存计数器**（可重算）。我做错某道推送题 → 该题 `state='error'` → 题型转 `suspect`。

**体量控制：以"时间预算"为主，题量只是结果**

要限制的**不是"每天最多几道题"，而是"每天最多花多少时间在重做上"**。因此：

| 层                  | 约束                        | 默认                            | 行为                             |
| ------------------ | ------------------------- | ----------------------------- | ------------------------------ |
| **① 每日时间预算（主约束）**  | "重做类"（每日错题 + 题型重推）每天最多花多久 | 合计 **40 分钟**，其中**每科 ≤ 15 分钟** | 按**预估用时**装题：`Σ(预估用时) ≤ 剩余预算`   |
| **② 单次题量**         | 每个题型一次推几道                 | 在预算内装题，**最少 2 道、最多 5 道**      | "不能只有一道"由下限保证；"不能太多"由上限与预算共同保证 |
| **③ 每科每日题型数（次约束）** | 同科同天最多几个题型                | **2 个**                       | 避免一天在太多题型间切换；取不到的顺延            |

> **注意"记背类"不受时间预算约束**：知识点记背与单词过关走**条数上限**（记背是"看/背"，不适用"做题用时"口径），仍按 L4.1 的"最高单日推送量 + 顺延"。

> **装题所需的"单题预估用时"见 L11**：`基准[科目][用时档位] × 速度倍率 × 题型系数`。本节只规定"按预算装题"与"超出顺延"。

**④ 容量摊平（关键：固定间隔硬排必然积压）**

算一笔账：若 **100 个题型**都处于高频（7 天一轮），每题按 5 分钟、每轮按 3 道 → **每天需求 ≈ 100 ÷ 7 × 15 ≈ 214 分钟**；而每日重做预算只有 **40 分钟**，两者差 5 倍以上。

因此把"7 天 / 15 天"当作**理想间隔**，**实际间隔由时间预算摊平**：

```
每天可用时间  slots  = 用户设定的每日重做预算（分钟）
每天需求      demand = Σ(各题型单轮预估总时长 ÷ 该题型理想间隔天数)
若 demand > slots  →  所有题型的实际间隔 × (demand ÷ slots)
```

- 上例：`demand ≈ 214`、`slots = 40` → 实际间隔 = `7 × 214 ÷ 40 ≈ **37 天**`；**只有需求降到预算以内才回到 7 天**。
- 学习计划页显示："**每日重做预算 40 分钟 ｜ 处于推送的题型 N 个 ｜ 预计每天需 X 分钟 ｜ 高频实际间隔约 Y 天（设定 7 天）**"；当 `X > 预算` 时**告警**并给三条建议：① 提高每日时间预算 ② 减少同时处于高频的题型（让更多题型停在低频或停推）③ 接受实际间隔变长。

> **时间预算是硬上限，间隔是软目标**：不造成每天负担靠预算，不积留靠摊平；代价是高频的实际间隔可能远长于设定值，**必须显示给用户，不能假装 7 天就是 7 天**。
> **推论**：100 个题型全覆盖高频 = 每天约 3.5 小时，不现实。所以**高频只能是少数题型的状态**（优先给 `suspect` 与最近解决的题型）——这正是降频与停推机制存在的意义。

**排队与顺延**

- **到期队列优先级**：`suspect`（曾掌握又出错，最该验证）> `solved(high)` > `solved(low)`；同级按"上次推送时间最久"优先。
- **顺延**：当日取不到的题型一律顺延到明天，**绝不突破当日预算**；学习计划页显示"待推题型 N 个 / 今日已推 M 个 / 约需 X 天清空"，让积压可见。

**两条边界**

- **"不必再练"不需要新状态**：某道错题我判断不必再练（如太简单），直接标 `mastered` 即可——"对我已不构成问题"就等于已掌握。
- **题目太少**：若某题型长期没有题目归入，节点页提示"该题型暂无题目"并给出直达未归位清单/挂题的入口。

### L4.3 英语单词过手

沿用批次 3 规格，不改动：`Word` / `WordSense` / `AcceptedAlias` / 会话与尝试 / 两种模式（任一义项、按词性分组无序逐义项）/ 规则匹配（规范化空格与标点，不做语义模糊）/ 失败后人工裁决，认可答案存为该义项的个人别名。

### L4.4 语文文言及古诗过手 **【暂缓】**

工作规划第 4d 条要求对语文文言与古诗做过手，但**判定方式未定**（默写？翻译？AI 检测？），因此本轮**暂缓**——**当前的记录库仍按 L2 的"纯记录与查阅"处理，不做任何排期**。

**预留**：`KnowledgeNode` 可承载篇目节点（如"《劝学》"），接口与状态机留出扩展位；本轮不做判定逻辑与页面。

## L5 批改链

**定位**：批改**我回收的组卷**——"组卷库生成卷子 → 我做完 → 拍照回收 → AI 批改"；也可用于单题作答或作业照片。数理化多为客观题且有标准答案，因此**优先规则判定，AI 只兜底**。

```
上传作答(照片/文字) ─▶ 资产归一化 ─▶ 题目定位(题号/作答切分)
   ─▶ 答案标准化(选项/数值/单位/表达式归一化)
   ─▶ 规则精确匹配 ──命中──▶ correct / incorrect
           └──未命中或主观题──▶ AI 判定 ──▶ correct / incorrect / uncertain
   ─▶ 结果页（逐题对错 + 标准答案 + 讲解）
   ─▶ 【用户决定】是否把某题标为"错题"（解耦，可批量）
```

- 作答录入可绑定单题（`question_id`）、整卷（`paper_id`），或只上传作业照片由 AI 定位题目。
- 主观题/证明题一律 `uncertain` 交我确认，**不猜分**；无标准答案的题不使用 AI 判分，直接 `uncertain`。
- **与标记解耦**：批改不自动改标记；结果页提供"标为错题"按钮，由我点击后写 `state='error'` 与标记日期；AI 的判定理由仅作可选备注。
- 学科范围：主要场景是数理化生客观题；语文英语作答也可批改（主观题一律 `uncertain`）。标记是题目通用属性，不按学科设特例。

## L6 组卷与导出链

**入口**：知识库 → 组卷页签（`/knowledge/papers`）。组卷是**同一套系统的两种使用逻辑**，共用"候选 → 固定版本 → 成卷 → 导出"底座：

| 逻辑              | 选题来源              | 由谁决定    | 用途                 |
| --------------- | ----------------- | ------- | ------------------ |
| **L6.1 手动组卷**   | 我在候选列表里勾选         | 我       | 阶段复习、专项训练、临时成卷     |
| **L6.2 规则自动组卷** | **完全由规则确定**，我只写规则 | 学习计划调度器 | 每日错题推送、题型重推、自定义周期卷 |

### L6.1 手动组卷

候选来源 = **全部题目池**（不限于错题，含语文英语题目），但**仅限状态为 `approved` 的题目**（`parsed` 草稿题不入卷）；筛选：学科、年级、**主题型（只列叶子题型）**、知识点、方法、**用时档位（短/中/长）**、状态标记、类别标记。
选题 → 排序/分值/大题名 → 记录 `question_version_id`（**版本固定，旧卷不因原题修改而变化**）。

### L6.2 规则自动组卷

一条规则的维度：

| 维度    | 可选条件                                                                                                     | 对应需求原话                        |
| ----- | -------------------------------------------------------------------------------------------------------- | ----------------------------- |
| 用途    | `daily_error` / `type_recheck`（按 L4.2 的频率与时间预算排期） / `custom`                                             | 每日错题推送、题型重推                   |
| 时间    | 录入日期窗口（如"前一天录入的错题"）、未过手时长                                                                                | "哪一天录入的题目"                    |
| 题型    | 指定题型或全部                                                                                                  | "哪一个题型"                       |
| 用时档位  | 该题型中**"长"档**（用时较长）的题优先                                                                                   | "难度大"——用"用时"表达，因为 **AI 不评难度** |
| 易错点命中 | 该题所属题型/知识点属于**错题数量最多**的一批                                                                                | "在我的易错点上"                     |
| 掌握速度  | **从标为错题到过手耗时最长**者优先                                                                                      | "我曾经掌握最慢的"                    |
| 状态过滤  | **仅 `daily_error` 用途**：只选未过手（`state='error'`）的题。**`type_recheck` 不走本行**——它的候选与过滤由 L4.2 定义（排除未过手错题、排除上一轮） | 与 L3 联动                       |
| 去重    | 同一题近 N 天内不出现在自动卷中                                                                                        | 避免重复推送                        |
| 成卷形态  | 题目数量、每题分值、是否分大题                                                                                          | —                             |

**选题器执行顺序（确定性、可复现）**：`状态过滤 → 时间/题型范围 → 打分排序（易错点命中 > 掌握最慢 > 用时档位 > 时间新旧）→ 去重（近 N 天）→ 截取数量 → 固定版本成卷`。
同规则、同一天的数据状态下**必须选出同一批题**，否则"当天任务固定"会被打破。

**健壮性（必须实现，否则早期会出错卷）**

1. **冷启动降级**：掌握耗时需历史积累，早期无数据 → 排序维度按序降级 `易错点命中（错题数量）→ 掌握最慢（无过手记录则跳过）→ 录入时间新旧`；**任一维度无数据都不得导致空卷**。
2. **数量不足**：生成实到数量的卷并标注"本次仅选出 N 题"，不凑数、不伪造。
3. **零结果**：不生成空卷；任务条目标记"无待推送题目"并说明原因（如"近 14 天已推送过"）。
4. **幂等**：同规则同一天只成一份卷（`paper_rule_runs` 去重）。
5. **`preview` 与 `generate` 调用同一选题器**，保证试算即所得。
6. **排除项优先**：`deleted`、非 `approved` 的题目一律不入卷。

**产出**：`Paper(mode='auto', status='draft')` + 固定版本 `PaperItem` + PDF（可选）→ 同时写入当天任务。
**与推送的关系**：L6.2 是 L7 的**题目来源引擎**——推送的产物是"按规则生成的一份题集"，不是消息流。"每日错题"与"题型重推"（L4.2 的加权随机抽题）都通过它成卷。

### L6.3 导出（两种逻辑共用）

学生版 / 答案版 / **解析版**（新增）→ 后端生成 PDF → 存 `generated-pdfs` → 登记 Asset → 下载链接。
**改造点**：导出改为异步 Job（返回 job_id，前端轮询 `/jobs/{id}`）。自动卷在列表中带 `auto` 标记，可查看/重导/删除/据此重新生成。

## L7 每日任务与推送链

**定位**：不是消息系统，而是**任务编排器 + 提醒**。

| 来源        | 触发                                                           | 任务类型                    |
| --------- | ------------------------------------------------------------ | ----------------------- |
| **知识点记背** | 数理化生中被标记"不会"的知识点按周期（默认 **2 天**）到期；**受最高单日推送量约束，超出顺延**        | `recite`                |
| 题型重推      | **定期到期即推**（高频 7 天 / 低频 15 天起）；进入门槛＝已过手错题占比 > 80%；降频与停推见 L4.2 | `question_type_recheck` |
| 单词过关      | 每日固定时间，按词库范围/数量/顺序选词                                         | `vocabulary`            |
| 每日错题      | 前一天标为错题且未过手（**仅数理化生**；由 L6.2 成卷）                             | `daily_error`           |
| 自动组卷      | 达到自定义组卷周期                                                    | `auto_paper`            |
| 批改待办      | 有未处理批改结果                                                     | `grading_review`（只提醒）   |

> **学科覆盖**：**知识点记背**、**题型重推**、**每日错题**都**仅覆盖数理化生**；**英语单词过关**仅英语；**语文英语知识库不产生任何推送**（纯记录与查阅）。

**机制**：`StudySchedule` 每类任务一条配置（开关、推送时刻 `HH:MM`、周期/间隔、范围、**最高单日推送量**）→ 后端进程内 asyncio 循环每 60 秒检查 → **启动补建**（服务未运行时错过的时间点，下次启动补建，幂等，一天一任务）→ `DailyStudyTask` + `DailyStudyTaskItem`（**当天固定，刷新不重选**）→ 提醒（主页与学习计划待办角标 + 可选系统通知，适配器 + 空实现兜底，**通知失败绝不影响任务生成**）。

**体量与顺延（两类口径）**：**记背类**（知识点记背、单词过关）受"最高单日推送量"约束，当日取 `min(队列, 上限)`；**重做类**（每日错题、题型重推）受"每日时间预算"约束（**单题预估见 L11**，装题与顺延见 L4.2）。共同点：**超出的一律顺延，绝不突破上限**；是否到推送日按 `last_pushed_date + 周期` 判断（对重启与中途改设置都稳健）。

**可设置项**（设置页 + `Setting` 表）：每类任务开关/推送时刻/周期；**记背类的最高单日推送量**；**重做类的每日时间预算（默认合计 40 分钟、每科 ≤ 15 分钟）**；每科每日题型数；每日单词量（1–200）；自动组卷周期；以及 L6.2 每条规则的用途/条件/数量/去重窗口。

## L8 日清 / 周清链

- **事项记录 `StudyItem`**：类型（作业/拓展/错题/其他）、学科、标题、说明、计划日期、状态、来源。
- **日清 `DailyClearance`**：按日期一条；内容 = 当天应完成清单 + 当天是否已拍错题上传 + 是否已搞懂。
- **周清 `WeeklyClearance`**：按周一条；内容 = 当周作业/拓展/错题的未完成集合，逐项勾掉。
- **自动汇总**：当天录入的错题自动进日清；当周未过手的错题自动进周清。
- **不做**与外部日程应用联动。

## L9 AI 通用对话链

**定位**：不绑定题目的通用对话；入口与拍题解析合并为同一板块的两个页签。多会话（新建/重命名/删除），消息复用 `messages` 表（靠 `kind='general'` 且 `question_id` 为空区分）；默认"学习助手"策略（高中六科优先，也可回答一般性问题）。

**与题内追问的区别**：题内追问绑定某题版本与步骤；通用对话无题目上下文，可自行贴图或粘贴内容。

**产出必须归档入库**：选中一段对话 → AI 整理为一条归档条目草稿 → 预览可编辑 + 选定主题型 → **我点"应用"才落库**（落点与条目结构见 L2.4 第 3 条）。这样按题型就能一次看到"这个题型怎么解、我当时是怎么学的、当时讨论的例题是哪道"。

**边界**：对话内容本身不成为题目、也不自动进知识库；对话里的模板题与值得沉淀的方法都只是**提案**，由我手动确认后写入。

## L10 账号与会话链（所有链路的前置）

本轮部署形态仍是**单机单人**，但账号体系落地，使将来云端多账号不必改表结构。

| 环节    | 设计                                                                               |
| ----- | -------------------------------------------------------------------------------- |
| 首次启动  | 无账号时**自动创建默认账号并自动登录**，零摩擦可用                                                      |
| 登录态   | 后端签发会话令牌存 `sessions`（**只存哈希**）；前端持有方式（HttpOnly Cookie 或 `Authorization` 头）在 P0 定 |
| 设密码   | 默认账号初始**无密码**，设置页可设/改（`hashlib.scrypt` + 随机盐）                                    |
| 切换/新建 | 设置页可退出、换账号登录、新建账号；本地多账号数据按 `owner_id` 自然隔离                                       |
| 归属强制  | 所有业务接口经 `get_current_user` 取当前账号；**所有查询与写入都带 `owner_id`**，禁止裸查询                  |
| 设备端   | 现有 `/device/*` key/scope 机制不动，不纳入本轮                                              |

**本轮不做**：多用户注册流程、邮箱/手机验证、找回密码、RLS、账号间共享协作（留到上云阶段）。

## L11 用时预估与时间预算（横切：L4.2、L7、组卷共用）

**为什么单独成节**：用时预估不只服务题型重推，也服务"每日错题"的装题与"组卷时显示这份卷大概要做多久"——所以基准表里有全部六科。

**单题预估（粗估，不做"自校准"）**

不用"实际用时移动平均"自校准——系统拿不到每题实际用时，逐题填又太麻烦。改为**可配置基准表 + 两个倍率**：

```
单题预估 = 基准[科目][用时档位] × 速度倍率 × 题型系数
```

| 基准表：科目 × 用时档位 | 短   | 中   | 长   |
| ------------- | --- | --- | --- |
| 数学            | 3   | 8   | 15  |
| 物理            | 3   | 8   | 15  |
| 化学            | 3   | 6   | 12  |
| 生物            | 2   | 5   | 10  |
| 语文            | 3   | 7   | 14  |
| 英语            | 2   | 5   | 10  |

（单位分钟，**起始默认值**；设置页用一张 6×3 表编辑，建议用几天后按自己的感受调一次。）

| 倍率                    | 默认（可调）                  |
| --------------------- | ----------------------- |
| **速度倍率**（全局，反映我的做题速度） | **1.0**                 |
| **题型系数**（大题额外加时）      | **大题 ×1.30** / 小题 ×1.00 |

- **用时档位由 AI 给**（`estimated_time_tier`：短 / 中 / 长），我可改；它**不是难度**（本设计无难度维度，"难题"是类别轴上的手选标签）。
- **大题的判定**：`question_type` 是否落在"大题集合"（解答题 / 计算题 / 证明题 / 作图题 / 实验题 / 应用题 / 阅读题…，设置页可增删），不是硬编码字符串匹配。
- **可能的重复计算**：AI 给档位时可能已考虑大题篇幅；若偏高，把大题系数设为 **1.0** 即关闭叠加。
- **不记录逐题实际用时**：只做"预算内的粗估"，预算本身留有余地——精度换零打扰。
- **可选（默认关闭）任务级计时**：记录"打开任务 → 标记完成"的时间戳差，**仅作参考显示**，**不自动改预估**（必然含中断时间）。
- **装题过程**：候选题按优先级排序后逐题累加预估用时，直到接近预算为止。

> **时间预算的两个消费者**：①"重做类"推送（每日错题 + 题型重推）按预算装题，超出顺延（L4.2 / L7）；②组卷时给出"预计完成时间"。**"记背类"与单词过关不走时间预算**，走条数上限（L4.1）。

# 10. 存储与安全

## 10.1 对象存储与压缩（沿用现状）

哈希寻址 `objects/<category>/<sha256[:2]>/<sha256><suffix>`；原子写（临时文件 → `fsync` → `os.replace`）；`path_for` 校验解析后仍在 `objects/` 内；压缩内容为 gzip(level 9) 的规范化 JSON（`.json.gz`）。
对象类别：`original-images`、`thumbnails`、`structured-content`、`generated-pdfs`、`raw-ai`；**新增** `handwriting-original`、`answer-images`、`submissions`、`import-sources`、`vocabulary-media`。

## 10.2 数据安全清单

| 项       | 设计                                                                                                                        |
| ------- | ------------------------------------------------------------------------------------------------------------------------- |
| API Key | 只在后端读取；设置写接口密钥字段**只写不读**，回显仅 `has_key: true`                                                                              |
| 路径穿越    | 保持现有防护，并覆盖新增的导入/手写/答案/作答路径                                                                                                |
| 上传校验    | MIME 白名单 + 10 MB 上限 + 可解码；文本导入增加大小与类型白名单，拒绝可执行内容                                                                          |
| 提示词注入   | policy 已声明用户内容为不可信；知识导入/批改/查词同样声明                                                                                         |
| 一致性检查   | **新增** `scripts/check-data.ps1`：扫描孤儿对象与缺失引用                                                                               |
| 备份      | **新增** 备份命令：SQLite（`VACUUM INTO` 或 WAL checkpoint 后复制）+ objects → `backups/<timestamp>/`，附 manifest 与校验和；恢复需校验和比对并重跑一致性检查 |
| 删除与清理   | 删除只影响关联记录；对象回收只在显式清理命令中做，且"先报告、后确认、可回滚（移入 backups）"                                                                       |
| 原件保留    | 手写原件、答案原件、作答原件**默认永久保留**；图片保留天数仅作用于中间产物（缩略图/临时）**【待确认】**                                                                  |
| 日志      | **新增**结构化日志落 `data/logs/`（含 AI 用量，不含 Key 与完整题干）                                                                           |
| 监听      | 127.0.0.1 + 本地 origin；不透出局域网                                                                                              |
| 时区      | 统一口径：**日期字段一律本地日历日，时间戳一律 UTC**；设置项含时区。否则"第二天推送""每半月重推"会算错                                                                 |
