# 多设备学习数据同步约束

本文件记录已确认的产品规则及实施顺序。云端目录与内容传输是两层不同的能力；仅有目录记录不能证明正文或文件已有另一份副本。

## 数据分层

- Supabase Auth 管理账号；Postgres 保存账号私有的完整**目录结构**：稳定条目 ID、类型、科目、节点父子关系、题目与知识节点关联、每条目的标题、正式题目不超过 120 字摘要、状态、修改时间、内容 SHA-256、各设备的持有状态。草稿不上传题干。
- 各设备的 SQLite 和 `objects/` 保存完整题库、图片、知识库正文，随后扩展至试卷、单词和学习历史。登录后扫描本机条目并与云端目录比较，只传输缺失或较旧的内容。
- Supabase Storage 仅作私有、短期中转；接收设备校验 SHA-256、原子落盘并提交 SQLite 后回执，才可清理中转对象。Storage 中转不是备份。
- 云端加密备份接口继续预留，待容量和密钥管理方案确定后启用。

## 同步与冲突

1. 每次本地安装保存一个稳定设备 ID，多个账号可共用该设备标识，但目录始终按账号隔离。登录后上报本机目录，读取该账号其他设备的目录；目录中的“存在”尚不代表完整副本已通过校验。
2. 对本机没有或版本较旧的条目建立传输请求；在线持有设备打包相关 SQLite 记录与文件，上传分块；目标设备下载、校验哈希、导入并回执。设备离线时请求保持待处理，在线后续传。
3. 同一条目在两台设备修改，以**修改时间较晚**的版本为准；相同时间以设备 ID 做确定性排序。覆盖前保留本机旧版本或冲突记录，避免误判时无法恢复。设备时钟偏差要在同步状态中显式显示。
4. 用户主动“删除草稿及原图”是全账号永久丢弃，须传播不可由旧目录覆盖的删除标记。离线设备重新上线时，若该题仍是草稿，就删除草稿和不被其他内容引用的原图。若另一设备已将同一题正式入库，则**入库优先**：云端标记草稿删除被正式版本覆盖，并保留正式目录；旧草稿仍清理，之后从正式版本所在设备重新获取完整内容。其他正式资料的“从此设备删除”只清理该设备副本，必须先确认另一台**在线并完成哈希校验**的设备持有完整副本；无法验证时拒绝删除。
5. 新设备首次登录若所有已有设备均离线，只能查看云端目录，无法立即恢复未曾中转的完整内容；等待任一持有设备上线。云端备份启用后才能覆盖所有设备丢失的场景。

## 容量边界

免费项目当前为 500 MB 数据库额度、1 GB 文件存储与每计费周期 5 GB 非缓存出站额度。Postgres 不保存原图、完整题干、长文或各设备完整 SQLite。目录按账号分页查询，图像与长文分块中转并在回执后清理。需要监测实际行大小、索引开销、Storage 峰值与出站流量；达到预算阈值时停止非必要中转，而非删除唯一副本。

## 实施状态

`supabase/migrations/20261025010000_learning_catalog.sql` 和本机 `cloud_catalog` 代码实现目录层：登录后后台更新目录，也可手动重试；可按设备列出题目、试卷、知识节点、条目、文件和单词的轻量索引；草稿删除标记同步后能清理其他设备上的草稿及非共享原图，云端拒绝旧草稿重新登记该题；若有正式版本，云端目录以正式版本为准。迁移文件也预留了私有中转表与 Storage 桶，但尚未建立上传、自动接收、完整数据导入、最后修改时间冲突处理、唯一副本删除保护，因此不得标记为“多设备同步完成”。
